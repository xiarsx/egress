# ADR-003：延迟桶 key 接受 xxh3 极低概率碰撞

- 状态：已接受
- 日期：2026-10-17
- 相关：设计 §6.2

## 背景

节点延迟用 TD-EWMA 维护，按 eTLD+1 分桶：Authority 常驻区 +
普通站点近似 LRU 区（默认 12 项，上限 32）。桶的 key 需要从域名快速算出，
且要在热路径附近高频使用（每次请求都要查"目标域名延迟"做 P2C 打分）。

候选方案：存完整域名字符串做 key（内存占用大、比较慢）、用密码学哈希
（如 SHA-256，安全但慢）、用非密码学哈希（xxh3，极快但有理论碰撞概率）。

## 决策

延迟桶 key 用 `xxh3-128(domain)`，**接受极低概率的碰撞**。
（初版 ADR 写 64 位；实现采用 Hash128，碰撞余量更大、代价可忽略，
2026-10-19 更正。）

## 放弃的替代方案

| 方案 | 否决理由 |
|---|---|
| 存完整域名字符串 | 10 万节点 × 多桶，内存与比较开销大；且 key 需要跨进程稳定（cache.db 持久化） |
| SHA-256 等密码学哈希 | 热路径附近高频调用，吞吐浪费在不需要的抗碰撞强度上；碰撞在这里不是安全问题 |
| 碰撞时链式处理/二次确认 | 把简单问题复杂化：碰撞的后果只是两个域名的延迟 EWMA 互相污染 |

## 后果

- 正面：key 为固定 128 位，查表 O(1)、零分配、跨进程稳定，满足 P2 热路径纪律。
- 负面（已接受）：极低概率下两个不同域名的延迟样本会混进同一个桶，
  导致 P2C 打分依据的延迟轻微失真。失真只影响"选 A 还是选 B"的相对排序，
  不影响正确性（不断连、不错路），且 EWMA 的时间衰减会自然稀释污染。
- 若未来观测到可测量的影响，可在不改 spec 的情况下换 key 算法
  （桶是内部结构，不对外稳定）。
